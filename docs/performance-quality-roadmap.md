# План повышения производительности и качества PsychologyApp

Цель: сделать Android-приложение быстрым, устойчивым и проверяемым на слабых устройствах без серверной части. План дополняет отдельные планы по ИИ-компаньону и прохождению практик; он не предполагает переписывать функции до измерения их стоимости.

## P0 — измерения и узкие места

1. [ ] **Снять базовый профиль приложения.** На слабом устройстве с Android 7/API 24 и на актуальном среднем устройстве измерить холодный/повторный запуск, время до первого действия, прокрутку каталога, открытие практики, ответ офлайн-чата, задержки SQLite, память и пропуски кадров. Результат: воспроизводимый сценарий, версия устройства/сборки и p50/p95 без пользовательских текстов.
2. [ ] **Задать бюджеты производительности.** На основе базового профиля определить пределы для запуска, ключевых переходов, чата, памяти и jank; добавить сравнение с базой в CI или отдельный device-runner. Результат: регрессия p95 более чем на 10% выявляется автоматически либо получает явное обоснование.
3. [ ] **Сократить критический путь запуска.** Разделить обязательную и отложенную инициализацию; перенести некритичные каталоги и прогрев ресурсов с UI-потока. Результат: первый интерактивный экран укладывается в бюджет из задачи 2, миграции не блокируют главный поток.
4. [x] **Запретить блокирующий ввод-вывод на UI-потоке.** Найти синхронные обращения к файлам/БД, `.Wait()` и `.Result` в сценариях запуска и навигации; добавить анализатор или проверку сборки с точечным allowlist. Результат: все оставшиеся исключения документированы, навигация не ждёт фоновые операции синхронно. — Аудит 2026-11-03: синхронных Dapper-запросов не найдено; `.Result` заменён на `await`; CI-проверка запрещает `.Result`/`.Wait()`/`GetAwaiter().GetResult()` в production-коде. Единственный allowlist — `PerfTrace` watchdog, который ждёт dispatcher на отдельном диагностическом потоке. Метаданные файлов (`File.Exists`/`Directory.Exists`) и ограниченные операции с файлами остаются в кэше аудио, импорте, удалении данных и проверке базы; это не ожидание `Task` и не чтение содержимого на UI-пути, кроме проверки 16-байтной сигнатуры уже скачанного аудио.
5. [ ] **Профилировать горячие запросы SQLite.** Снять планы `EXPLAIN QUERY PLAN` для главных экранов и истории, убрать подтверждённые full scan/N+1, добавить только необходимые индексы. Результат: топ-запросы укладываются в бюджет, миграции индексов проверены на существующей базе. — Добавлены проверки планов для истории сообщений (`IX_ChatMessages_Session`), списка чатов (`IX_ChatSessions_UpdatedAt`), истории настроения (`IX_MoodEntries_RecordedAt`), истории тестов (`IX_TestResults_TestId`), последней заметки практики (`IX_SessionResults_ItemKey`) и цитат (`UX_Quots_Text`). Миграция v15 удаляет дублирующий индекс сортировки чатов и проверяет сохранность данных. Замеров времени на Android ещё нет.
6. [x] **Ограничить объём чтения и вычислений списков.** Перевести крупные истории/каталоги на ограниченные выборки и проекции нужных полей; не загружать все записи ради одного экрана. Результат: набор на 50 000 тестовых записей возвращает только видимый диапазон и не растёт линейно по памяти. — Истории настроений, результатов тестов и практик используют ограниченные SQLite-выборки; каталог пользовательских техник поддерживает LIMIT/OFFSET. Добавлен SQLite-тест на 50 000 строк: запрос истории возвращает только последние 50 записей в правильном порядке.
7. [ ] **Проверить прокрутку длинных списков.** Измерить кадры и allocations в Release; включать виртуализацию, переиспользование элементов или нативный Android-рендер карточек только там, где профиль подтверждает выигрыш. Результат: список из 1 000 элементов укладывается в бюджет jank и не создаёт видимые рывки.
8. [ ] **Ограничить кэш и срок жизни ресурсов.** Профилировать изображения, аудио, JSON-каталоги и ViewModel при навигации; добавить освобождение и верхние границы для подтверждённых кэшей. Результат: после 20 циклов открытия/закрытия тяжёлых экранов память стабилизируется в пределах бюджета устройства.

## P1 — ускорение ключевых офлайн-сценариев

9. [x] **Измерить горячий путь русского NLU.** Добавить отдельный benchmark для нормализации, лексического анализа и выбора ответа; оптимизировать только операции, которые занимают значимую долю p95. Результат: есть сравнение до/после, а существующие наборы точности и кризисной безопасности проходят без регрессии. — Добавлен отдельный model-free benchmark `tools/PsychologyApp.OfflineNluBench` (2 000 прогревочных + 20 000 замеров на этап, 8 синтетических фраз). Windows/.NET 10 x64: анализатор p50/p95 0,48/1,02 → 0,34/0,55 мс; полный pipeline 0,48/0,98 → 0,35/0,54 мс; выделения анализа 402 → 22 КБ/сообщение (−95%). Это host baseline; Android/AOT здесь не измерялся.
10. [x] **Удалить поддержку локальных LLM из приложения.** Убрать загрузку весов, ONNX GenAI runtime, настройки модели и модельный путь из чата; оставить детерминированные офлайн-ответы. Результат: Android-приложение и его DI не ссылаются на LLM/runtime/загрузчик, модельные тесты и ресурсы удалены, сценарии офлайн-чата остаются покрыты тестами. — Удалены runtime, DI, загрузчик, настройки, проект, model-only reply guard и модельные тесты; production source, project references и workflows не содержат остатков. Все пять platform-independent test-проектов прошли (2 773 теста); Android compile не достигнут из-за отсутствующего SDK (`XA5300`).
11. [ ] **Ввести отмену и back-pressure для фоновых операций.** Передавать `CancellationToken` из жизненного цикла страницы в загрузки, поиск, экспорт и генерацию; объединять повторные запросы. Результат: закрытая страница не обновляется поздним ответом, многократные быстрые нажатия не запускают дублирующие операции. — Отмена покрыта для chat lifecycle, audio download, quote search и CSV share; `AsyncCommand` и навигационные тесты защищают от повторных запусков. `DataBackupPage` теперь отменяет активные импорт, экспорт backup, сводку и лог при уходе; токен проходит в backup/summary API, чтение файла и `AtomicFileWriter`. Два теста подтверждают остановку backup export и генерации сводки без открытия share. Аудит остальных длительных операций остаётся.
12. [ ] **Ускорить открытие и восстановление локальных данных.** Профилировать чтение каталога, состояние чата и черновиков; кэшировать только неизменяемые данные с явной инвалидизацией. Результат: переходы укладываются в бюджеты задачи 2, после изменения языка/контента нет устаревшего экрана. — Каталоги имеют кэш/прогрев, пользовательский прогресс и черновики читаются из SQLite; задержки и память на Android не профилированы, поэтому точечные кэш-изменения пока не обоснованы.

## P1/P2 — надёжность и инженерное качество

13. [x] **Сделать запись локальных документов устойчивой к прерыванию.** Для JSON и экспорта проверить временный файл, атомарную замену и восстановление сохранённой копии. Результат: аварийное завершение во время записи не уничтожает последнюю корректную версию данных. — Пользовательские документы хранятся в зашифрованной SQLite `AppMetadata`, а запись выполняется одним атомарным UPSERT. Backup JSON, сводка специалисту и CSV дневника теперь сначала полностью записываются во временный файл в той же папке и только после flush-to-disk публикуются заменой целевого файла. Тест симулирует сбой посреди записи: старый файл остаётся целым, временный удаляется; отдельный тест проверяет успешную замену.
14. [x] **Проверить миграции и конкурентный доступ к БД.** Прогнать обновления пустой и заполненной базы, повторный запуск миграций, одновременные чтения/записи и длительные операции. Результат: миграции повторяемы, нет потери данных, зависаний и необработанных `SQLITE_BUSY` на стресс-наборе. — Повторный `EnsureSchemaAsync` проверяется на заполненной базе после миграций v13→v14 и v14→v15; миграция v15 сохраняет запись чата и удаляет избыточный индекс. Тесты покрывают пустую базу, заполненную v1, миграции v12/v13 и последовательность SQLite operation lane. File-backed stress-тест: 30 параллельных читателей и 40 записей через независимые соединения завершаются без ошибки и с сохранением всех записей.
15. [x] **Закрыть тестами рискованные пользовательские переходы.** Расширить автоматические сценарии для черновиков, повторных команд, отмены, выбора практики, кризисного маршрута и восстановления после перезапуска. Результат: каждый сценарий проверяет ожидаемое состояние и отсутствие повторной записи результата. — Существующие тесты покрывают восстановление диалога и черновиков, double-tap команд и навигации, отмену, кризисный переход и завершение практики без повторной записи.
16. [ ] **Добавить тесты отказов офлайн-хранилища.** Проверить повреждённую БД/JSON, заполненный диск, заблокированный файл, прерывание приложения и отсутствие сети. Результат: приложение показывает безопасный исход, сохраняет восстановимые данные и не падает без понятного сообщения. — Проверяются schema newer-than-app, отказ ключа шифрования, повреждённые/слишком большие backup, отмена импорта и обрыв атомарного экспорта (старый файл сохраняется, временный удаляется). `SQLITE_FULL`-тест ограничивает SQLite `max_page_count` и подтверждает сохранность прежнего результата; Windows-тест блокирует целевой файл, проверяя что старый экспорт остаётся целым и temp удаляется. Cancellation-тест отменяет запись после заполнения temp-файла и проверяет сохранность прежнего target. Аварийное завершение между flush/rename остаётся непокрытым.
17. [ ] **Проверить доступность на реальном Android.** Пройти ключевые экраны TalkBack, системным увеличением текста до 200%, обеими темами и крупными шрифтами. Результат: у интерактивных элементов есть понятные подписи, текст не обрезан, контраст соответствует проверкам проекта.
18. [ ] **Автоматизировать полноту и качество локализации.** Проверить ключи ресурсов во всех семи поддерживаемых языках, fallback и длинные переводы на узком экране. Результат: нет отсутствующих ключей; русский и английский проходят редакторскую проверку, остальные локали не переполняют основные элементы. — Presentation.Tests теперь проверяет, что каждый публичный текст разрешается во всех семи локалях; существующие тесты сверяют RU/EN ключи и placeholders, дополнительные переводы — неизвестные ключи и placeholders. Проверка длинных строк на устройстве остаётся.
19. [x] **Закрепить офлайн-приватность тестами.** Проверить сетевые адаптеры, телеметрию и логи на предмет отправки пользовательских текстов; подтвердить локальную обработку чата и практик. Результат: тесты ловят попытку отправки личного текста, в логах остаются только технические сведения, кризисные проверки проходят. — Статический аудит production-кода: единственный `HttpClient` — GET встроенных аудиоресурсов; других HTTP/WebRequest/TCP клиентов и SDK телеметрии не обнаружено. Форма обратной связи открывает системный email/SMS/share только по явному действию. `ChatService` не принимает HTTP-транспорт (проверяется тестом). Локальный логгер записывает шаблон события, категорию, уровень и тип исключения, не значения и не сообщение исключения; отдельный тест это фиксирует. Офлайн-кризисные проверки проходят в Application-наборе.
20. [ ] **Ввести Release-гейт Android.** В CI собирать Release для минимальной API и актуальной Android-цели, запускать пять test-проектов, проверять уязвимости зависимостей, размер пакета и отсутствие новых предупреждений. Результат: установка, первый запуск, обновление с предыдущей версии и офлайн-сценарий проходят на эмуляторе; подпись берётся только из защищённых CI secrets. — В репозитории уже есть Release APK smoke на API 34, пять тест-проектов в release workflow и NuGet vulnerability workflow; workflow security очищен от ссылки на удалённый LocalLlm. Проверка минимального API, обновления установленной версии, offline flow и размера пакета не покрыта.

## Правило выполнения

Сначала выполнить задачи 1–2, затем выбирать оптимизации по измеренному эффекту. Для каждого изменения сохранять сравнение до/после и тесты корректности. Не включать платформенную оптимизацию, если она не даёт воспроизводимого выигрыша на Release-сборке.
